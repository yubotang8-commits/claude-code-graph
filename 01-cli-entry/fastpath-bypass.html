CLI 快速路径旁路

组件 01-cli-entry · 入口与引导 · 静态流程图

敲下 claude 之后、进入主程序之前的岔路口：cli.tsx 的 main() 按代码顺序逐个试探快速路径——--version、无参开关、daemon worker、子命令（bridge / daemon / job）、tmux 组合——命中即预热配置、动态加载对应子系统并运行到结束；只有全部未命中，才落到完整 CLI（main.tsx）。

深入细节（证据与考据）
  • 证据来源：src/entrypoints/cli.tsx:76-360（main() 优先级 if 链）、cli.tsx:11-69（模块顶部副作用）、src/daemon/main.ts:52（daemonMain 子命令分发：start/stop/status/bg/attach/logs/kill）、src/daemon/workerRegistry.ts:26（runDaemonWorker，退出码 78=EX_CONFIG 表示永久失败、supervisor 不重试）、src/bridge/bridgeMain.ts:2001（bridgeMain 参数解析与会话循环）、src/cli/handlers/templateJobs.ts:14（templatesMain：list/new/reply/status）、src/services/acp/entry.ts:27（runAcpAgent：stdin/stdout 上的 NDJSON ACP 协议）。
  • bridge 四道门的顺序是刻意的：认证检查必须先于 GrowthBook 门——没有认证时 GrowthBook 缺用户上下文会返回过期的默认 false（cli.tsx:199-203 注释）；门依次为 OAuth/bridge token（:205）、GrowthBook 运行时开关（:208）、最低版本（:212）、组织策略 allow_remote_control（:218-221）。
  • 失败面：门检查是原子单元——任一失败 exitWithError 即退、不留状态；--version 打印不可部分生效。可部分生效的单元：bridge 路径 enableConfigs 已发生（配置缓存写入）后才因认证/策略失败退出；daemon 路径 initSinks 已挂。唯一跨路径共享写点：profileCheckpoint 埋点（cli.tsx:88/107/190 等）与 process.exitCode（如 --daemon-worker 门关时置 1，cli.tsx:169）。
  • 考据注记（与 CLAUDE.md 的差异）：文档漏了 -V 变体（cli.tsx:80）；daemon 路径实际门是 feature('DAEMON')||feature('BG_SESSIONS')（cli.tsx:231，文档只写 DAEMON）；文档所列 environment-runner / self-hosted-runner BYOC 快速路径已在提交 f38f8f20 / b59461ae 中删除，声明过时；--acp（:124-129）、weixin（:131-157）、autonomy（:249-263）、job（:297-305）为文档未列的快速路径；ps/logs/attach/kill 是 deprecated 别名映射到 daemon 子命令（:278-294），--bg 的匹配先于它们（:266）。
  • 本图合并：无参快速路径六条（--dump-system-prompt、--claude-in-chrome-mcp、--chrome-native-host、--computer-use-mcp、--acp、weixin）合并为一个判定节点；子命令组（bridge 五别名 remote-control/rc/remote/sync/bridge、daemon、--bg、job 与 new/list/reply 别名）合并为一个判定节点；autonomy 快速路径（读状态后 process.exit(0)）省略。tmux 组合未接管时确实会落回默认路径继续执行（cli.tsx:330-338 注释 "fall through to normal CLI"）。
