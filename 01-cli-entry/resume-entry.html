会话恢复链路（--continue / --resume）

组件 01-cli-entry · 入口与引导

从「带上 --continue 或 --resume 启动」到「带着完整历史消息回到对话界面」的全过程：参数分流 → 缓存清理 → 定位会话文件 → 重建会话状态 → 挂载 REPL。

处理步骤 判定分支 替代路径 / 模式 开始 / 结束 旁注机制 灰色小字 = 对应源码模块（仅作定位锚点）
深入细节（证据与考据）
  • 证据来源：src/main.tsx（3669-3736 continue 分支、3986-4398 resume 分支级联）、src/utils/conversationRecovery.ts（loadConversationForResume：定位 + 反序列化 + SessionStart 钩子消息）、src/utils/sessionRestore.ts（processResumedConversation：换回 sessionId/工作树、恢复 agent 定义与归因）、src/dialogLaunchers.tsx:148-171（launchResumeChooser）、src/screens/ResumeConversation.tsx（onSelect 在组件内原地完成恢复并直接渲染 REPL）、src/replLauncher.tsx:14-31（launchRepl 挂载）。
  • 两条分支各自独立调用 loadConversationForResume：continue 传"无参"取最近会话（会跳过仍在后台写入的 daemon/--bg 会话）；resume 传 UUID / 标题 / .jsonl 路径。图中把两条分支的公共步骤（缓存清理、读取、状态恢复、挂载）合并为共享主干，实际是两段对称代码。
  • --resume 传非 UUID 字符串时，先按自定义标题精确匹配：唯一命中即直接恢复（跨工作树）；未命中或多命中则作为选择器的预填搜索词。.jsonl 文件路径恢复仅对内部用户（USER_TYPE=ant）开放。
  • 交互式选择器路径不走 launchRepl：ResumeConversation 屏在用户选中后于组件内执行同样的 switchSession / 恢复 agent 定义 / 组装恢复包，随后原地渲染 REPL——图中以"选择器内原地恢复"节点表达，最终与主干在挂载 REPL 前汇合。
  • 兄弟分支未展开：--teleport / --remote 走远端会话（CCR）子流程，与本地恢复共用缓存清理但后续不同；teleport 直接传 ID 时还有仓库错配对话框与 git 状态校验。
  • 失败语义：找不到会话是干净报错退出（exitWithError，无半装配 REPL）；catch 路径 logError + process.exit(1)。中断后残留状态很少：globalConfig.numStartups 已 +1、worktree 若已建则留在磁盘（saveWorktreeState 已写）；信任与 onboarding 已持久化，重跑即恢复。
  • fork 语义（--fork-session）：复制消息但保留启动时的新 sessionId，旧会话文件原样保留；内容替换表需重新播种到新会话（否则旧 tool_use 被判为冻结、全量重发导致缓存失效）。
  • MCP 连接不写入恢复包：各 resume 分支将 initialState.mcp 置空，重连交给 REPL 挂载后的钩子（useManageMCPConnections）逐台完成——慢服务器只影响恢复后的第二轮对话。
  • 考据注记：main.tsx 行号随提交漂移（考据时约 5640 行，自述文档写 ~5674）；"恢复包"对应代码中的 ProcessedResume（messages / fileHistorySnapshots / contentReplacements / agentName / agentColor / restoredAgentDef / initialState）。
