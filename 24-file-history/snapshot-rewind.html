深入细节（证据与考据）
  • 证据来源：src/utils/fileHistory.ts（trackEdit:88 / makeSnapshot:200 / rewind:349 / createBackup:750 / copyFileHistoryForResume:924）、src/QueryEngine.ts:653-668（每条用户消息触发 makeSnapshot，fire-and-forget）、src/utils/sessionStorage.ts:1108-1122（insertFileHistorySnapshot 落 JSONL）与 2287-2311（last-wins 快照链重建）、src/cli/print.ts:749-784（--rewind-files 独立模式：校验目标必须是 user message UUID，回滚成功后 gracefulShutdownSync(0) 直接退出）、src/screens/REPL.tsx:6546-6553 与 src/components/MessageSelector.tsx:261/351（消息选择器回滚入口与逐条 diff 预览）、packages/builtin-tools（FileEditTool:431 / FileWriteTool:260 / NotebookEditTool:314 / BashTool:530 编辑前调用 trackEdit）。
  • 调用约定：trackEdit 必须在真正写文件之前调用（备份保存的是编辑前内容）；FileEditTool 在读-改-写临界区外 await 它——过时检查失败只会留下一个未使用的备份，不会污染状态。
  • 三相提交防竞态：捕获（无副作用读状态）→ 异步备份 → 写回前重检（并发 trackEdit 可能已抢先把该文件补进快照，此时放弃写回）。v1 备份名按路径哈希确定性生成，重复调用不会互相覆盖。
  • 首张快照：由第一条用户消息的 makeSnapshot 建立（trackedFileBackups 可能为空表）；trackEdit 若发现没有最近快照会 logError 并跳过。
  • 增量判定（checkOriginFileChanged）：stat 比较 mode/size；原文件 mtime 早于备份即视为未变（免读内容）；否则读双方内容逐字比较。文件被删除记 backupFileName=null 删除标记，回滚时对应执行 unlink 删除新增文件。
  • 开关（fileHistory.ts:65-80）：globalConfig.fileCheckpointingEnabled !== false 默认开启；CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING 关闭；SDK/非交互会话默认关，需 CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING 显式开启。
  • 上限与淘汰：MAX_SNAPSHOTS=20 滚动窗口；snapshotSequence 单调递增计数供 useGitDiffStats 作活跃信号。内存淘汰后磁盘备份文件仍在，但对应回滚点失效。
  • 持久化与恢复：快照以 file-history-snapshot 条目写进会话 JSONL（与消息同文件混排）；resume 时 isSnapshotUpdate=true 的条目按 last-wins 覆盖同 messageId 槽位重建快照链，再由 fileHistoryRestoreStateFromLog 装回 AppState。
  • rewind 是纯文件系统副作用（不改 FileHistoryState）：REPL 消息选择器支持恢复代码/会话/两者三种组合，选中前逐条预览 ±行数；--rewind-files 必须搭配 --resume 且不能带 prompt（print.ts:586-594）。
  • 失败模式：备份创建失败仅跳过该文件（logEvent 不阻塞整个快照）；单文件恢复失败只影响该文件粒度；resume 拷贝部分失败时整张快照不落 JSONL（failedSnapshots 统计）；硬链接失败回退 copyFile，EEXIST 幂等跳过。
