工具权限批准流：一次「问人」的完整旅程

权限级联判定说 ask 之后的事——useCanUseTool 把答案包成 Promise 挂起 → ToolUseConfirm 入队（FIFO）→ REPL 每帧焦点仲裁决定弹不弹 → PermissionRequest 终端确认框等用户按键 → 决策 resolve 回 query 循环（放行执行或生成拒绝结果）→ onDone 出队，下一条顶上。队列清空 = 循环退出。
第 1 轮 · 完整：入队 → 弹框 → 打字插曲 → 拍板 → 回传 第 2 轮 · 简短：总是允许 → 规则落盘（循环再走一条） 退出 · 队列清空 → 焦点归还 → 回合结束

🖥 终端确认框 PermissionRequest 按工具定制的变体
这一站：13+ 种工具变体（Bash / FileEdit / …，permissionComponentForTool 分发）；用户不按键超时会发系统通知「Claude needs your permission to use …」；Ctrl+C 走 onAbort 兜底拒绝。
终止：决策 resolve 且 onDone 出队；队列清空后 getFocusedInputDialog 离开 'tool-permission' → 恢复 spinner / PromptInput 焦点；等待总时长入账 totalPausedMs（转时长消息会扣除这段等人时间）。
故障面：resolve 与出队是两步——resolve 先放 query 走，出队才驱动下一个框渲染，两步之间中断会卡队列（下帧渲染兜底继续出队）；用户 ESC / abort 时 resolveIfAborted 兜底 resolve，防 Promise 悬空卡死 query；打字抑制只藏框不清队列（PromptInput 显示 Waiting for permission…）；并发入队按固定优先序插队渲染。
