权限判定级联

09-permission-pipeline · 工具执行前的权限关卡

模型每次要用工具，都要走这道关卡：先听用户配置的钩子裁决，再按「拒绝规则 → 询问规则 → 工具自检 → 模式 → 放行规则」的级联判定；拿不准就问人——auto 模式交给 AI 分类器代判，普通模式排队弹终端确认框，问完可以把「总是允许」写进配置，下次同类请求直接放行。

处理步骤 判定分支 替代路径 / 模式 开始 / 结束 旁注机制 灰色小字 = 对应源码模块（仅作定位锚点）
深入细节（证据与考据）
  • 证据来源：src/services/tools/toolExecution.ts（权限关卡与拒绝分支）、src/services/tools/toolHooks.ts（PreToolUse 钩子裁决优先级）、src/hooks/useCanUseTool.tsx（REPL 侧 canUseTool 装配与 ask 分流）、src/utils/permissions/permissions.ts（级联判定 + 外层模式变换 + auto 分类器）、src/hooks/toolPermission/handlers/interactiveHandler.ts（确认框与多路竞速）、src/hooks/toolPermission/PermissionContext.ts（resolveOnce 与规则持久化）、src/screens/REPL.tsx（确认框队列渲染）、src/types/permissions.ts（三态决策类型）。
  • 级联完整顺序（permissions.ts:1179-1340）：1a 整工具 deny 规则 → 1b 整工具 ask 规则（Bash 沙箱例外：autoAllowBashIfSandboxed 时沙箱命令跳过 ask 规则改走自检）→ 1c 工具自检 checkPermissions → 1d 自检拒绝 → 1e 需用户交互工具（连 bypass 都要问）→ 1f 内容级 ask 规则（bypass 免疫）→ 1g 敏感路径安全检查（.git/.claude 等，bypass 免疫）→ 2a bypassPermissions / plan+bypass 模式 → 2b 整工具 allow 规则 → 3 passthrough 转问人。
  • 外层变换（permissions.ts:473-977）：级联结果为 allow 时重置 auto 模式连续拒绝计数；为 ask 时——dontAsk 模式直接转拒绝；auto 模式（或 plan 中激活的 auto）先走 acceptEdits 快路径（Agent/REPL 工具除外，防 VM 逃逸绕过分类器）、再走安全工具白名单、最后调用 yolo 两段式分类器 API；分类器被拦截时计数+1，连续拒绝超限回退问人，不可用按 iron_gate 门决定拒绝或回退，transcriptTooLong 回退问人。PowerShell 在 auto 模式默认要求显式人工批准。
  • 钩子裁决细节（toolHooks.ts:340-436）：PreToolUse 钩子给 allow 时若工具需用户交互或上下文要求 canUseTool 则仍走常规判定；无需交互时仍要过 deny 规则检查（ask 规则也要弹框）；钩子给 deny 直接生效；无结论则带 forceDecision 走常规判定。
  • 问框期间的多路竞速（interactiveHandler.ts:138-708）：确认框入队（REPL.tsx:5805-5822 只渲染队首）的同时，bridge（claude.ai 远端弹窗）、channel（Telegram/iMessage 等渠道转发）、PermissionRequest 钩子、Bash 允许分类器后台检查并行开跑，resolveOnce 的 claim() 保证只有最先返回的一路生效。Bash 投机分类器另有 2 秒宽限（useCanUseTool.tsx:199-253）：赶在弹框前出结果就免弹。协调者 worker 先等自动检查，群蜂 worker 经邮箱转发给 leader。
  • 持久化非原子（PermissionContext.ts:139-147）：onAllow 先 persistPermissions（PermissionUpdate 写 settings.json + setToolPermissionContext 更新内存规则），决策再经 resolveOnce 单次回传 toolExecution；两步之间被打断会留下「下轮自动放行、本轮被拒」的半持久状态。行为不是 allow 时（toolExecution.ts:1037-1146）合成 is_error tool_result，拒绝原因（及用户反馈）一并回给模型。
  • 考据注记：级联中 1e/1f/1g 三类「免疫检查」与 2a 模式检查的相对顺序是本图「④ 敏感路径免疫检查」一行的合并表达；auto 分类器的快路径实际有 acceptEdits/白名单两条（图中已列）；「ask」是 PermissionBehavior 三态之一而非权限模式（模式为 default/acceptEdits/plan/auto/bypassPermissions/dontAsk）；「级联判定顺序」旁注共 7 行对应源码 1a-1g/2a/2b/3 的 10 个分支（1d 工具自检拒绝并入 ③，1e-1g 并入 ④）。
