组件架构：重试与模型回退

07-retry-fallback · 组成模块与调用关系

「请求失败后的自愈链」由这些模块协作：宿主把发请求打包成可重试的尝试 → 编排器对每次失败分类（能修就修、该等就退避等待、连续过载就换模型）→ 支撑模块管凭据、调速与遥测；两条紫色分支是最终出路（换备用模型整轮重跑、降级为非流式请求）。

组成模块（实线箭头 = 调用/控制流） 回退分支（改变模型或请求方式） 降级出路 / 外部组件 跨尝试共享状态 灰色小字 = 源码模块锚点（非代码内容） 「服务器过载 / 流式创建失败(404)」= 状态码 529 / 404，见深入细节
深入细节（证据与考据）
  • 证据来源：src/services/api/withRetry.ts:170-517（重试主循环）、:52-55（默认 10 次）、:62-89（前台来源判定，后台任务过载直接放弃）、:232-251（认证/陈旧连接后重建客户端）、:267-314（快速档短重试与冷却降级）、:326-365（连续 3 次过载 → 抛换模型信号）、:384-427（上下文超限自动调小输出上限）、:431-512（指数退避+抖动、持久模式心跳）、:693-784（错误分类 shouldRetry）；src/services/api/claude.ts:1874-1952（宿主把建客户端+发流式请求包进 withRetry、转发重试进度消息）、:2723-2815（流式创建 404 → 降级非流式重跑）、:2884-2889（展开不可重试信封取原始错误）；src/query.ts:890-896、:1152-1208（捕获换模型信号 → 换备用模型、清半截回复、整轮重跑）；src/services/api/errors.ts:425-934（错误 → 用户可读消息）；src/utils/fastMode.ts、src/utils/auth.ts、src/services/analytics/index.ts。
  • 考据注记：模块清单取自 api-streaming.json 的 retry-orchestrator / api-error-mapping 及其边界描述；同清单其余组件（参数组装、SSE 事件消费、provider 分流、三个兼容层）分属 05/06 号组件页，本图仅以虚线盒引用客户端工厂（每次尝试可被强制重建）。
  • 省略/合并：errors.ts 同目录的 errorUtils.ts（8 行 re-export 薄包装，from @ant/model-provider）并入错误翻译器锚点；「凭据修复」合并了 OAuth 401/403-token-revoked 刷新与 AWS/GCP 云凭据缓存清理三条路径；重试遥测的多个上报点（withRetry/claude/query 各自调用）合并为一盒。
  • 状态码与判定规则：图上「服务器过载」= HTTP 529（含流中 overloaded_error 消息），「流式创建失败(404)」= 流创建阶段 404；完整重试判定见 withRetry.ts:693-784（408/409/429/5xx、x-should-retry 响应头优先、mock 限流错误不重试、订阅用户 429 不重试、CCR 模式 401/403 视为瞬时故障等）。
  • 分歧如实：模型回退默认仅对非订阅（PAYG）用户且主模型为 Opus 时生效，FALLBACK_FOR_ALL_PRIMARY_MODELS 环境变量可放开（withRetry.ts:326-365）；无备用模型的外部用户连续 3 次过载直接产出一条错误消息而非回退。「上下文超限自愈」在源码注释中标注为向后兼容保留——API 现改用 stop_reason 返回该情况。
  • 相关交互：流式回退发生时主回合循环用「墓碑」消息丢弃已产出的半截回复（query.ts:953-969，详见 02-query-turn-loop 页）；非流式回退由 claude.ts 侧触发并回调 onStreamingFallback 通知上游。
