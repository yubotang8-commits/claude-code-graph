深入细节：证据与考据

一、时间线与源码对应（逆向仓库只读取证，file:line 为定位锚点）

  • 重试主循环：最多给 10 次机会（默认值，可被环境变量覆盖）—— src/services/api/withRetry.ts:170-189（机会上限/连击阈值/退避基数见 52-55、786-791）
  • 用户中断立即放弃：等待或重试前发现打断信号，安静退出、不出错误消息 —— withRetry.ts:190-192、491（本页"中断演示"的依据）
  • 错误分诊清单：过载/限流/超时/连接错误/5xx 值得重试；请求本身有问题、服务明确说"别重试"则立刻放弃 —— withRetry.ts:693-784
  • 凭证失效或连接变"陈旧" → 强制重建客户端再重试 —— withRetry.ts:232-251
  • 过载连击计数：连续 3 次（阈值 3）且有备用模型 → 抛换模型信号 —— withRetry.ts:326-365；无备用模型的外部用户连击 3 次 → 一条"反复过载"终止错误（src/services/api/errors.ts:166），而非换将
  • 后台任务（标题、摘要、分类器等）遇过载直接放弃不重试，防止级联放大 —— withRetry.ts:62-89、318-324（本页演示的是"前台"路径：用户正等着结果）
  • 指数退避：0.5 秒基数、每次失败翻倍、0–25% 随机抖动、封顶 32 秒 —— withRetry.ts:530-545
  • 屏幕重试提示：退避前交给上层展示；持久模式下每 30 秒心跳一次 —— withRetry.ts:431-512 → src/services/api/claude.ts:1944-1951
  • 换模型信号原样上抛：API 客户端层不吞，吞掉会让回退变成"只报错不重跑"—— claude.ts:2728-2730
  • 主循环接令换将：换备用模型整轮重跑 —— src/query.ts:890-896；清残片与补"作废"回执（防下次请求格式非法）—— query.ts:1152-1165
  • 重试档案跨尝试存续并影响下一次请求参数（如输出上限预留优先）—— withRetry.ts:120-125、claude.ts:1673-1677

二、考据注记（摘自 API 子系统证据 api-streaming.json）

  • 重试编排组件边界：被 API 客户端两处调用（流式 claude.ts:1874 / 非流式 865），向上抛三类信号（放弃重试 / 换模型 / 用户中断），依赖凭据刷新、极速模式、遥测模块。
  • 刻意设计：流式请求的过载与非流式回退的过载共享连击计数（claude.ts:2684 预置 1），让"连击 3 次换将"的总数与请求模式无关——上游 issue #1513 的修复。
  • 并列分支未入本时间线：极速模式三条降级支线（短等待保极速 / 长等待降标准速度 / 超额永久禁极速）withRetry.ts:267-314；上下文超限自愈（自动下调输出上限再试）384-427；无人值守持久重试（限流/过载无限重试、5 分钟封顶、分块睡眠）96-104、431-512。
  • 分歧记录：连击计数仅在"非订阅用户 + 非自定义主力模型"或显式开关开启时才累积（withRetry.ts:331-333）——本页演示的是计数生效的路径。
  • 未核验项（静态考据边界）：Bedrock/Vertex/Foundry 云 SDK 分支内部行为未逐行读（client.ts:153-298 仅确认构造参数）；VCR 录制回放层包裹全部模型调用，其对请求的包装点未确认，对重试的影响未覆盖。

三、用语对照（图例补充）

  • 529 = 远端"过载"状态码，本页核心概念：过载连击阈值 3 即源码的连击上限；429 = 限流（同为"会自己好"）；413/400 = 请求本身有问题（超限/格式），不重试。
  • "换将"= 切换备用模型重跑；"退避"= 失败后等待，0.5 秒起步、每次翻倍、带随机抖动、封顶 32 秒；"宽心话"= 编排退避前交给屏幕的重试提示。
