acp-link 接入 RCS 全链路

组件 20-acp · 远程控制 / ACP / Daemon / 后台会话

acp-link 代理如何把自己登记到 Remote Control Server 并让 Web UI 远程使用：两步注册（REST 登记 + WS identify 握手）→ 前端经 /acp/relay 中继双向收发 → 断线后指数退避、重跑完整两步。

处理步骤 判定分支 替代路径 / 模式 开始 / 结束 旁注机制 灰色小字 = 对应源码模块（仅作定位锚点）
深入细节（证据与考据）
  • 证据来源：packages/acp-link/src/server/start-server.ts（ACP_RCS_URL/TOKEN/GROUP 读取与校验、relayWs 虚拟客户端注册）、src/rcs-upstream.ts（registerViaRest、identify/identified、1s→30s 退避重连）、src/server/dispatch.ts（JSON-RPC 与 legacy 双协议分发）；packages/remote-control-server/src/routes/v1/environments.ts、src/services/environment.ts（storeCreateEnvironment + 自动建 ACP 会话 + storeBindSession）、src/routes/acp/index.ts（/acp/ws 与 /acp/relay/:agentId 路由）、src/transport/acp-ws-handler.ts（handleIdentify 校验、markOnline/Offline、inbound 总线发布）、src/transport/acp-relay-handler.ts（中继订阅与 sendToAgentWs 直投）、src/transport/event-bus.ts（按 channelGroupId 的总线、seqNum、5000 条截半）；web/src/acp/relay-client.ts（前端中继客户端，token 走 API key/uuid 通道）。
  • 考据注记：manifest 的 10 个站点拆画为 18 个主干节点（RCS 服务端行为单列为节点）；下行链路（前端→agent）是 sendToAgentWs 直投、不经 EventBus——manifest units 所述 outbound SessionEvent 在当前实现里仅测试代码出现，agent 侧对 outbound 事件的订阅当前无人发布；REST 注册失败不阻塞本地 /ws 服务（connect() 拒绝仅 warn）；identify 被拒（Agent 不存在 / workerType≠acp）时 reject，实际靠 WS onclose 进入退避循环；RCS 对空闲连接按 3×keepalive 判死（close 1000 'client inactive'）；虚拟 relayWs 让 RCS 来的消息与本地 /ws 客户端共用同一套 dispatch handler。
  • 故障面：REST 注册失败 → 重跑完整两步；identify 拒绝 → error 消息；agent WS 断开 → markOffline（环境记录保留、可重连）+ relay 收 status{connected:false}；中继期直投失败 → 前端收 'Agent connection lost'；消息逐条原子转发，EventBus 超 5000 条截半可能丢旧事件（SSE 消费者需及时拉取）；RCS 关停时 close 1001 server_shutdown。v2 code-sessions/worker 协议未在图中展开（考据阶段未逐行核实）。
