  • 匹配与执行：src/utils/hooks.ts:1739（按事件名 + matchQuery——工具调用类事件用工具名、会话类事件用来源/原因——过滤 matchers）、:2088（统一执行入口）、:2128-2135（工作区信任门，未信任整体跳过）、:3538 / :3594 / :3636（工具前/后/失败三类包装函数）。

  • 考据注记（省略与合并）：省略了 AsyncHookRegistry（异步钩子完成后的续流回调）、hooksConfigSnapshot（启动期配置快照）、fileChangedWatcher（文件变更触发）、postSamplingHooks、apiQueryHookHelper、skillImprovement、ssrfGuard（HTTP 支路的内联防护，并入六支路描述）等次要模块；「其他时机」盒内合并了通知 / 压缩 / 问询触发点，未逐一单列；共享底座实际分散在 AppState（会话级注册表）与 bootstrap/state（插件注册表 / 耗时统计），图中合并为一条横条。
  • 存疑：27 事件常量在 src/entrypoints/agentSdkTypes.js:4-32 与 src/entrypoints/sdk/coreTypes.ts:25-53 两处完全重复定义（内容一致，后续是否失同步存疑）；配置合并优先级存在张力——hooks.ts:1852-1854 注释称 Map 去重「后合并者胜出」，而 hooksSettings.ts:230-271 又按来源顺序排展示优先级（插件/内置垫底），冲突场景下的实际胜者未逐条验证，如实存疑。
