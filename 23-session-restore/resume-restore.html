会话恢复 resume 全链路

组件 23-session-restore · 状态与会话持久化

从「敲下恢复命令」到「旧对话原样回到屏幕上」的完整过程：定位会话文件 → 逐行读 JSONL → 回溯重建对话链 → 净化反序列化 → 原子换脑切换会话身份 → 认领原文件 → REPL 带旧消息挂载，之后的续写直接追加进同一个文件。

深入细节（证据与考据）
  • 证据来源：src/main.tsx:3669-3736（--continue 分支）、src/main.tsx:4292-4336 与 4392-4398（--resume 按 UUID / 无参数弹选择器）、src/utils/conversationRecovery.ts:485-630 与 :167-243（定位与净化反序列化）、src/utils/sessionStorage.ts:3566-3590（loadTranscriptFile）、:2106-2131（buildConversationChain）、:1567-1571（adoptResumedSessionFile）、src/utils/sessionRestore.ts:410-564（processResumedConversation 换脑编排）、src/utils/fileHistory.ts:924-1048（copyFileHistoryForResume）、src/cost-tracker.ts:131-176（成本恢复）、src/screens/REPL.tsx:2123-2348 与 :1486/:2326（会话内 /resume 换脑回调与消息数组）、src/commands/resume/resume.tsx:121-164（LogSelector 选择）。
  • 读日志一步实为「读尾部轻量元数据 → 需要时再读全量」两级：--resume 选择器列表只读每个 JSONL 的尾部 64KB（lite 日志），选中后才 loadFullLog；图中合并为一个节点。
  • 反序列化是净化式部分生效：filterUnresolvedToolUses 丢弃未配对 tool_use、filterOrphanedThinkingOnlyMessages 丢弃孤 thinking、filterWhitespaceOnlyAssistantMessages 丢弃纯空白 assistant（conversationRecovery.ts:190-205）；被检出的中断被改写成合成的 "Continue from where you left off." 续接消息 + 哨兵 assistant，保证下一次 API 请求配对合法。
  • 换脑是原子同变：switchSession 一次同时改 STATE.sessionId 与 STATE.sessionProjectDir（bootstrap/state.ts:462-473），onSessionSwitch 信号联动 ~/.claude/sessions/<pid>.json PID 文件（concurrentSessions.ts:98-108）。
  • fork（--fork-session / /branch）刻意跳过 switchSession 与 adoptResumedSessionFile：保留启动时的新 sessionId，靠 useLogMessages 挂载时把消息重写进新 JSONL，并补种子 content-replacement 条目（sessionRestore.ts:453-464），旧会话文件原样保留仍可独立恢复。
  • 会话内 /resume 与 CLI 路径的差异：REPL 回调先对旧会话跑 SessionEnd hooks、保存旧会话成本再换脑（REPL.tsx:2162-2230），且元数据恢复前必须先 clearSessionMetadata 清缓存（set-if-truthy 语义，:2241-2247）；CLI 冷启动路径无旧会话可收尾。
  • 恢复完成后流程汇入「会话消息落盘生命周期」的持续循环：新消息由 useLogMessages 增量转交 recordTranscript，追加进被 adopt 的原 JSONL；进程退出时 reAppendSessionMetadata 把标题/标签等元数据重追加到文件尾部 64KB 窗口内。
  • 失败面：loadConversationForResume 返回 null → exitWithError('No conversation found')（main.tsx:3684/4306）；catch → logError + process.exit(1)（main.tsx:3728-3736）；跨项目 resume 只给剪贴板命令不直接换（resume.tsx:132-159）；快照拷贝部分失败时整快照不落 JSONL（fileHistory.ts:1020-1044）；成本恢复按 lastSessionId 匹配、不匹配则从零（cost-tracker.ts:93-97）。
  • 考据注记（来自子系统考据 uncertainties）：远程持久化（persistToRemote/hydrateFromCCRv2）的门控与注册入口未接通核验；cli/print.ts 的 headless resume 完整调用链未走读到行号；两者对本图主干无影响，仅记录。
