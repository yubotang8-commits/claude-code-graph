插件安装与运行时注入全链路

组件 18-slash-skills-plugins · 斜杠命令 / 技能 / 插件

从「安装 / 启用一个插件」到「运行中的会话真正获得它的命令、hook、agent 与 MCP 工具」：清单落盘 → 缓存全清 → 重新加载 → 四路注入 → MCP 重连；未触发自动刷新时由用户手动执行 /reload-plugins 沿回边重新进入刷新链。

  • 节点映射：清单 7 站点展开为 13 个主干节点——「资产分流」站点拆成主干「四路拆分」+ 右侧「四个落点」；refreshActivePlugins 内部实际顺序为 clearAllCaches → loadAllPlugins → 命令/agent 并行 → MCP/LSP 缓存槽预热 → 写 AppState（reconnectKey+1）→ LSP 重初始化 → loadPluginHooks，图中 B7-B9 画成线性，实际 hook 注册与 MCP effect 在状态写入后并发进行。
  • 刷新触发三路：/reload-plugins 命令（reload-plugins.ts:37）；后台 marketplace 安装完成后自动刷新——仅限「新装」（result.installed.length>0 才调 refreshActivePlugins，PluginInstallationManager.ts:135-146，失败则退回 needsRefresh 通知；纯更新 updated>0 只置 needsRefresh 不自动刷新，:166-179）；headless 下 CLAUDE_CODE_SYNC_PLUGIN_INSTALL=1 在首次查询前自动刷新（print.ts:1786-1797，pluginLoader.ts:3142 处委托全量加载器）。/plugin 菜单安装/启停只写盘并置 needsRefresh 提示，不自动刷新（refresh.ts 头注释 PR 5b/5c，installPluginFromMarketplace 返回消息即提示 Run /reload-plugins to activate）——即右侧「等待手动刷新」支路与回边。
  • 落盘双文件：安装/卸载写 installed_plugins.json（addPluginInstallation:406 / removePluginInstallation:452，saveInstalledPluginsV2 单文件原子写，installedPluginsManager.ts:370-394）；启用/停用写 settings.json 的 enabledPlugins（PluginSettings.tsx:310-321）。loadAllPlugins 把两者合并后才决定每个插件的 enabled 状态。
  • 终止语义：安装/启停操作以 UI 的 onDone 或 CLI 输出终止；运行时注入以 refreshActivePlugins 完成为定型点，此后各下游在下一次读取/事件时看到新状态：命令表由 REPL 经 useMergedCommands 并入 AppState.plugins.commands（REPL.tsx:1097-1098，响应式生效）；hook 由 hooks-core 在下次事件匹配时从注册表读到（getMatchingHooks）；MCP 工具在连接建立后进 AppState.mcp.tools 再入工具池。无长驻循环。
  • 故障面：安装落盘是单文件原子写；refresh 的缓存清理是多步级联——loadAllPlugins / loadAllPluginsCacheOnly / loadPluginCommands / loadPluginHooks / agent 定义等多个独立 memoize 必须全清，漏清一个会出现新旧混用（commands.ts:616-622 注释明确指出嵌套 memoize 失效陷阱，loadPluginHooks.ts:17 特为此引入 clearPluginCache）。单个插件加载失败只产生 PluginError 进 AppState.plugins.errors（useManageMCPConnections.ts:95-132 去重展示；refresh.ts:207-217 mergePluginErrors 保序去重），不阻断其他插件。
  • 考据注记：hook 注册是「清后注册」原子对（gh-29767：旧实现把清空放在缓存清理里，导致插件 Stop hook 在任何插件管理操作后静默失效）；clearAllCaches 只修剪已移除插件的 hook（gh-36995），新增 hook 仍等 /reload-plugins，与命令/agent/MCP 行为一致。禁用插件的 MCP 连接要等 pluginReconnectKey bump 触发 excludeStalePluginClients 才真正断连，防止幽灵工具残留。插件 MCP 服务器键名 plugin:名:服务（scope 'dynamic'），与手动配置同内容的按「手配优先」内容级去重（dedupPluginMcpServers）。installed_plugins.json 的内存启动快照不被后台操作更新（installedPluginsManager.ts:68-73 注释），跨进程安装需重启或手动刷新才可见。
