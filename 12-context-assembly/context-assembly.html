一次请求的上下文组装

组件 12-context-assembly · 上下文与系统提示

从「用户按回车」到「请求发往 API」之间，模型看到的系统提示与上下文是怎么被拼出来的：三件套并行取件 → 提示来源仲裁 → 环境快照追加 → 用户上下文前置 → 身份头与缓存切块。

深入细节（证据与考据）
  • 证据来源：src/utils/queryContext.ts（fetchSystemPromptParts 三路并行）、src/constants/prompts.ts:423-543（getSystemPrompt 静态段+动态段注册表+边界标记）、src/context.ts:36-189（getGitStatus/getSystemContext/getUserContext）、src/utils/systemPrompt.ts:41-123（buildEffectiveSystemPrompt 仲裁）、src/screens/REPL.tsx:3470-3506 与 src/QueryEngine.ts:294-335（两个入口层）、src/query.ts:647-649 与 899-901（appendSystemContext / prependUserContext 落点）、src/utils/api.ts:317-485（splitSysPromptPrefix / appendSystemContext / prependUserContext 实现）、src/services/api/claude.ts:1433-1479 与 3368-3392（身份头+nonce+buildSystemPromptBlocks）、src/constants/system.ts:30-46（身份前缀三选一）。
  • 入口差异：REPL.tsx:3470-3485 直接 Promise.all 并行调三件套（同一批里还混入 fast-mode 熔断检查）；QueryEngine.ts:298-310 走 fetchSystemPromptParts 封装；SDK side_question 路径用 buildSideQuestionFallbackParams 重建同一前缀以保缓存命中（queryContext.ts:88-179）。
  • 顺序注记：manifest 站点顺序把 prependUserContext 列在 claude.ts 定型之后；实际代码中它在 query.ts:899-901 作为 callModel 的调用参数先执行——messages 侧先包好，system 侧随后在 claude.ts 定型。本图按代码实际顺序绘制。
  • customSystemPrompt（--system-prompt）设置时，getSystemPrompt 与 getSystemContext 在取件阶段就被跳过（queryContext.ts:61-72 返回空值），所以「替换」分支同时意味着环境快照段为空、cache 前缀整体不同。
  • 仲裁细节：agent 提示在 proactive 模式下是「追加到默认提示之后」而非替换（systemPrompt.ts:99-113）；override（loop 模式）完全替换一切；appendSystemPrompt 恒追加在尾部。QueryEngine 路径实际是内联拼装（QueryEngine.ts:331-335）而非调 buildEffectiveSystemPrompt。
  • REPL 会把 coordinator 上下文与「终端未聚焦」状态并入 userContext（REPL.tsx:3486-3495），QueryEngine 也合并 coordinator 字段并可能注入 memory-mechanics 提示（QueryEngine.ts:312-335）——图中未展开。
  • splitSysPromptPrefix 有三种模式（global-cache 边界模式 / 工具化缓存模式 / 默认 org 模式），取决于 shouldUseGlobalCacheScope() 与 1P provider 判定，默认构建实际命中哪条路径未验证。buildSystemPromptBlocks（claude.ts:3368-3392）内部调用 splitSysPromptPrefix，并给 cacheScope 非 null 的块加 cache_control。
  • CLAUDE_CODE_SIMPLE=1 时 getSystemPrompt 直接返回 3 行极简提示（prompts.ts:429-433）；BREAK_CACHE_COMMAND 注入（ant-only 调试机制）默认关闭。
  • git status 截断文案写 "2k characters" 但 MAX_STATUS_CHARS=1000（context.ts:20 与 :88，上游文案遗留）；git 命令失败时 getGitStatus 返回 null，仅缺该段不中断（context.ts:104-110）。
  • memoize 缓存失效点：/clear（caches.ts:84）、compact（postCompactCleanup.ts:72，reason 'compact'）、/memory、settingsSync、sessionRestore。cache-break nonce 的 once 标记删除是 best-effort try/catch（claude.ts:1461-1467）；always 标记保留直到 /break-cache off。
