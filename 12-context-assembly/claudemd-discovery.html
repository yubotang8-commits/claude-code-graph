CLAUDE.md 层级发现与 @include 递归加载

组件 12-context-assembly · 上下文组装

从「会话第一次需要用户上下文」到「一份拼接好的 claudeMd 文本」：先判定是否被禁用，再按 系统托管 → 用户全局 → 项目层级（根→当前目录）→ 附加目录 → 记忆入口 的顺序逐个读文件，@include 引用递归展开，最终格式化成单一字符串，随之后的每次请求前置注入对话。

深入细节（证据与考据）
  • 触发与落点：getUserContext（src/context.ts:155，memoize 化）由 queryContext.fetchSystemPromptParts 与 defaultSystemPrompt / systemContext 三件套并行调用（REPL.tsx:3470-3485、QueryEngine.ts:298-310）。产出的 claudeMd 之后由 utils/api.ts 的 prependUserContext 渲染为消息数组最前的 <project-instructions> isMeta user 消息（每轮请求前置），currentDate 等其余字段走 <system-reminder> 注入。
  • 禁用判定（context.ts:162-168）：环境变量 CLAUDE_CODE_DISABLE_CLAUDE_MDS 硬关；--bare 且无 --add-dir 时跳过自动发现但尊重显式 --add-dir（"skip what I didn't ask for, not ignore what I asked for"）。
  • 加载顺序（claudemd.ts:2-26 文件头注释）：Managed（如 /etc/claude-code/CLAUDE.md，策略级总是加载）→ User（~/.claude/CLAUDE.md 与 ~/.claude/rules/*.md，需 userSettings 开启，User 类型始终允许外部 include）→ Project（root→cwd 逐目录的 CLAUDE.md、.claude/CLAUDE.md、.claude/rules/*.md，需 projectSettings）→ Local（CLAUDE.local.md，需 localSettings）→ --add-dir 附加目录（env CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD 门控，默认关；SDK 默认 settingSources=[] 时也照读，因属用户显式动作，:935-976）→ AutoMem MEMORY.md 入口（isAutoMemoryEnabled）与 TeamMem 入口（feature('TEAMMEM')，:978-1006）。越晚加载优先级越高（模型更关注）。
  • @include 递归（claudemd.ts:617-684）：支持 @path、@./relative、@~/home、@/absolute 四种写法，仅在叶子文本节点生效（代码块/代码字符串内不解析）；processedPaths 以归一化路径 + 符号链接解析结果双登记防环防重（:628-647，兼容 Windows 盘符大小写）；深度上限 5（:536）；外部引用（不在 originalCwd 内）默认丢弃，Project 需 hasClaudeMdExternalIncludesApproved 配置批准或 forceIncludeExternal，User 始终允许（:665-669、:797-800）。
  • 内容清洗（:342-399，parseMemoryFileContent 纯函数）：非文本扩展名直接跳过（防二进制入上下文，TEXT_FILE_EXTENSIONS 白名单）；frontmatter 剥离并提取 globs（条件规则字段）；HTML 块注释剥离（marked lexer，gfm:false）；AutoMem/TeamMem 入口截断（truncateEntrypointContent，200 行/25KB）；contentDiffersFromDisk 与 rawContent 记录清洗后与磁盘原文的差异。数据单元 MemoryFileInfo{path,type,content,parent?,globs?,contentDiffersFromDisk?,rawContent?}——@include 递归给 parent 字段指向包含者。
  • 失败面：ENOENT / EISDIR 静默跳过（:401-415，文件不存在属预期）；EACCES 记 tengu_claude_md_permission_error 遥测不抛错（:408-414）；嵌套 worktree（.claude/worktrees/）向上走同时穿过 worktree 根与主仓根，主仓目录的 Project 文件被跳过去重、CLAUDE.local.md 因 gitignore 只存在于主仓仍加载（:858-883）；tengu_paper_halyard gate 开启时 getClaudeMds 直接丢弃 Project/Local（:1157-1165）。中断后 memoize 为空则下轮全量重走目录，天然可恢复。
  • 考据注记（文档与代码矛盾）：文件头注释（:23）称"被含文件作为独立条目排在包含者之前"，代码实际先 push 主文件、include 随后（:660-681 "parent before children"），以代码为准。
  • hooks 与遥测：首次加载记一次 tengu_claudemd__initial_load 遥测（:1024-1039）；InstructionsLoaded hooks fire-and-forget，逐文件触发（AutoMem/TeamMem 被有意排除——它们是独立记忆体系不算 instructions），parent 文件报 reason 'include'（:1041-1070）；nextEagerLoadReason / shouldFireHook 一次性标志使 compact 后重载报 'compact' 而非 'session_start'（:1087-1107）。
  • 缓存语义：getMemoryFiles 与 getUserContext 双层 memoize，会话内定型——磁盘上的 CLAUDE.md 中途修改不生效（陈旧即部分状态）；/clear（resetGetMemoryFilesCache）、compact（postCompactCleanup.ts:63-72，同时清 getUserContext 外层缓存，否则内层缓存清了也永远轮不到重走、hook 永不触发）、/memory、settingsSync、sessionRestore 清缓存；worktree 进出等只为正确性的失效走 clearMemoryFileCaches（不触发 hook）。
  • moth_copse 门（:1141-1150，本 fork GrowthBook 本地默认开）：开启时 filterInjectedMemoryFiles 把 AutoMem/TeamMem 从 claudeMd 滤除，记忆内容改经 relevant_memories 预取按需浮现——索引与召回双通道的组合语义无运行时验证（考据不确定点：若预取又失败，模型整轮看不到任何记忆内容）。
  • 副产物：setCachedClaudeMdContent（context.ts:176 → bootstrap/state.ts:1185-1190）把 claudeMd 文本另存进模块级 STATE，供 yoloClassifier 免循环依赖读取。
