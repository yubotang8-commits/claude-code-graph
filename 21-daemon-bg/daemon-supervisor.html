daemon supervisor：拉起 worker 与后台会话

组件 21-daemon-bg · 流程图（静态）

「让 Claude 在你关掉终端后继续干活」：敲下 claude daemon start 后，监督者登记自己、拉起远程控制 worker；worker 崩了按退避节奏重启、病得重就熔断停手；另一条 --bg 支线把会话丢到后台跑，靠 <pid>.json 文件互相发现。

深入细节（证据与考据）
  • 证据来源：src/entrypoints/cli.tsx:164-176/231-242/265-294（三条快速路径）、src/daemon/main.ts:52-101（daemonMain 子命令分发）/230-325（runSupervisor）/330-428（spawnWorker 与退避判定）、src/daemon/workerRegistry.ts:26-113（runDaemonWorker、exit 78/1 映射）、src/daemon/state.ts:22-101/109-157（状态文件、探活、stopDaemonByPid）、src/bridge/bridgeMain.ts:2810-2962（runBridgeHeadless 前置检查与注册）、src/cli/bg.ts:279-338（handleBgStart 与 -p 检查）、src/cli/bg/engine.ts:9-49、src/cli/bg/engines/detached.ts:18-52、src/utils/concurrentSessions.ts:59-109/116-161（registerSession 与 <pid>.json）。
  • 考据注记：崩溃处理是 spawnWorker 里 child.on('exit') 的事件回调，与主线程 await abort 并行发生——本图为了线性可读，把回路画在等待节点之前；workerRegistry 目前只有 remoteControl 一种 kind（workerRegistry.ts:33-40），runSupervisor 的 workers 数组也只有这一项；exit 78 取自 sysexits.h 的 EX_CONFIG（workerRegistry.ts:15）；「快崩」阈值是启动后 10 秒内退出、连续 5 次（main.ts:394-403），跑满 10 秒会同时重置 failureCount 与退避时长；退避上限 120 秒、无 jitter（与 bridge 侧轮询退避不同）；预建会话（DAEMON_WORKER_CREATE_SESSION=1）失败被标记为 non-fatal（bridgeMain.ts:2945-2947）。
  • 旁路细节：auth 缺失按 transient 处理（workerRegistry.ts:88-92 的 onAuth401 会重新查 token，supervisor 下一轮重启可能自愈），而信任未接受、非 localhost 的 http base URL、worktree 模式无 git 仓库三者是 permanent（bridgeMain.ts:2831-2869）；worker 的 stdout/stderr 每行被 supervisor 加两格缩进转发到自己的终端（main.ts:364-375）。
  • 后台支线：bg 子命令由 daemonMain 与 --bg 快速路径双入口进入，都汇到 handleBgStart；tmux 引擎在 Windows 不可用（本机环境只验证了 detached 路径，tmux 侧细节未逐行核实）；<pid>.json 由子进程自己在主 CLI 启动时写入（main.tsx 的 registerSession 调用），退出时 registerCleanup unlink，进程崩溃留下的死文件靠 listLiveSessions 的探活扫描顺带清扫（concurrentSessions/bg.ts:16-45）。
  • 状态落点：~/.claude/daemon/remote-control.json（DaemonStateData：pid/cwd/startedAt/workerKinds/lastStatus，supervisor 内存 WorkerState{backoffMs,failureCount,parked,restartTimer}）、DAEMON_WORKER_* 环境变量束（spawnWorker 注入 → runBridgeHeadless 解析为 HeadlessBridgeOpts）、~/.claude/sessions/<pid>.json（SessionEntry：kind/name/logPath，onSessionSwitch/updateSessionName 原地 patch）。
