组件架构：延迟工具按需加载

10-deferred-tools · 组成模块与调用关系

60 个内置工具加上全部 MCP 工具，若每次请求都全量携带会撑爆上下文。这个组件的解法：请求里只带核心工具，其余全部「延迟」——模型需要时先用搜索工具发现名字、再经执行代理转交，而「谁被发现过」就记在对话历史里。

组成模块（实线箭头 = 调用/数据流） 旁路机制（不等模型先搜） 外部组件 共享底座 灰色小字 = 源码模块锚点（非代码内容）
深入细节（证据与考据）
  • 延迟判定：packages/builtin-tools/src/tools/SearchExtraToolsTool/prompt.ts:69-78（isDeferredTool：不在核心名单且未标 alwaysLoad 即延迟）；src/constants/tools.ts:137-179（CORE_TOOLS 核心名单，实测 29 项：Bash/PowerShell 2 个 + 27 个独立工具名）。
  • 请求侧剔除：src/services/api/claude.ts:1151-1204（filteredTools 永不包含延迟工具，仅保留 SearchExtraTools 入口；源码注释明示保持工具数组稳定以护 prompt cache；无延迟工具且无 MCP 在连时整体关闭该机制）。
  • 搜索实现：SearchExtraToolsTool.ts:350-530（select: 精确/逗号多选、discover: 只看说明、关键词、+词必含四种问法；:479 关键词得分×0.4 + TF-IDF×0.6 加权合并，权重可用环境变量覆盖；:542-601 委托目标执行与渲染）。
  • 语义索引：src/services/searchExtraTools/toolIndex.ts:80-149（对延迟工具的名称/搜索提示/描述三字段分别加权建 TF-IDF 向量，复用技能搜索 localSearch.ts 的分词与相似度函数）；索引按工具名集合缓存失效。
  • 会话预取：src/services/searchExtraTools/prefetch.ts:10-24（复用技能预取的取词函数；维护独立的 discoveredToolsThisSession 集合，上限 500 截到 400；结果供 UI 订阅）。
  • 发现集：src/utils/searchExtraTools.ts:458（「Found N deferred tool(s)」文本模式是发现集的唯一持久载体）、:489-498（extractDiscoveredToolNames 从消息历史重建，压缩边界携带续传）、:513/610-670（deferred_tools_delta 增量附件路径）。
  • 执行代理：packages/builtin-tools/src/tools/ExecuteTool/ExecuteTool.ts:66-219（找不到工具/未发现守卫/当前不可用/目标 schema safeParse 预校验/validateInput/权限 deny 检查/委托 targetTool.call 并透传进度，结果包装为 {result, tool_name}）。
  • 考据注记：CLAUDE.md 称核心名单 38 个，实测 29 个（判断为文档漂移；同目录测试注释「7+19」亦为陈旧值）。名单告知有两条路径：默认请求前注入静态名单块；灰度中改用增量附件（随消息持久化、压缩边界续传），图中并入「请求构建」未单独画。预取的「会话发现集合」与执行守卫用的「对话历史发现集」是两个独立状态：预取结果不解除执行守卫（守卫只扫消息历史）。Tool.shouldDefer 字段（Tool.ts:450-453）疑似上游遗留：判定实际只看核心名单与 alwaysLoad，未发现该字段的运行时消费者。三个工具发现类工具（SearchExtraTools/ExecuteExtraTool/StructuredOutput）本身在核心名单内、永不延迟。完整的工具执行生命周期（zod 校验、hook、权限级联、并发分区）属组件 08/09，本图只画到「转交目标工具」为止；模块层面省略了搜索提示文案生成（prompt.ts）与描述缓存，已并入对应模块。
