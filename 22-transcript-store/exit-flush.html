🔔 退出扳机 用户 / 终端 / OS
谁能扣扳机：/exit、Ctrl+D（REPL 正常退出）· Ctrl+C=SIGINT · kill=SIGTERM · 终端断开=SIGHUP
print 模式（-p）有自己的 SIGINT 处理，不让位
🧭 退出编排 gracefulShutdown.ts
一条编排线：防重入 → hook 预算 → failsafe → exitCode → 终端复位+提示 → 2s cleanup 竞速 → hooks → 遥测(≤500ms) → forceExit
🧹 清理注册表 cleanupRegistry.ts
注册制：模块在运行期把清理函数塞进全局 Set，退出时 Promise.all 并发执行 —— 谁注册谁善后
💾 会话 JSONL sessionStorage · Project
📄 ~/.claude/projects/<sanitizePath(cwd)>/<sessionId>.jsonl —— 尾部 64KB 窗口
readLiteMetadata 只读这段--resume 列表靠窗口内的元数据认会话
📎 挂尾收尾 history · hooks · 遥测
都排在会话落盘之后：提示历史 flush、SessionEnd hooks（≤1.5s）、遥测（≤500ms）—— 各有硬时限，超时就放弃
⚡ kill -9 / 断电现场SIGKILL 无法被捕获 —— 下方灰显的退出流程一行都没有执行
完整：会话消息主体运行期 100ms 批量写早已落盘 · append-only 旧内容不损
部分：最后 ≤100ms 的队列尾巴攒在内存里没来得及 appendFile —— 最坏半行 JSON
缺失：元数据尾部重追加custom-title / tag / last-prompt 没回到 64KB 尾窗口 → --resume 列表退回 firstPrompt
缺失：终端复位 + resume 提示终端可能残留 alt screen 脏状态
怎么恢复 / 兜底
  • claude --resume <sessionId>：消息照常恢复（append-only 的好处）
  • 标题丢了 → /rename 重设；终端脏 → reset 重开
  • 就算不是 kill -9：cleanup 挂死也有 failsafe max(5s, hook 预算+3.5s) 强退 —— 「挂死的退出」不存在
  • 对比：远程持久化失败是硬失败 → gracefulShutdownSync(1)（sessionStorage.ts:1376-1379）
